# CMUDict Relocation & Stats Requirements

## Context
- Today the CMUDict JSON lives in `apps/web/src/data/dict/cmudict.json` and is generated by `packages/helper-scripts/src/cmudict-to-json.ts`. The web API consumes it in `apps/web/src/app/api/g2p/_core/dictionary.ts`.
- We want CMUDict (and the new stats payload) to be treated as canonical shared data, exported from `packages/shared-data`, and consumed by apps via that package—not as app-local assets.
- We also want a learner-facing stats surface that uses those shared artifacts (no marketing fluff, functional guidance only).

## Goals & Outcomes
- Single source of truth for CMUDict JSON inside `shared-data` so multiple packages can reuse it without duplicating copies.
- New stats JSON generated from CMUDict, also stored and exported from `shared-data`.
- Helper scripts emit both artifacts into `shared-data`; consumers import via `shared-data` rather than app-relative paths.
- A stats page (or section) in the web app that surfaces learner-helpful CMUDict insights (phoneme frequency, ambiguity, stress, syllable shapes) using the shared stats payload.

## Scope
- Relocate CMUDict JSON output path to `packages/shared-data` (keep it data-only; no UI strings).
- Add a stats generation step that reads the CMUDict JSON and writes a stats JSON alongside it in `shared-data`.
- Export both JSON payloads (and minimal types) from `packages/shared-data` so downstream imports are stable.
- Update `apps/web` consumers to read from `shared-data` rather than `apps/web/src/data`.
- Define the UX/content requirements for the stats surface that reads the shared stats JSON.

### Out of Scope
- Changing CMUDict source, parsing rules, or adding non-English dictionaries.
- Altering the existing G2P API contract beyond its data source path swap.
- Persisting user-specific analytics; this remains aggregate-only data.

## Data Artifacts & Locations (target)
- `packages/shared-data/data/dict/cmudict.json`: canonical CMUDict payload with existing meta fields (formatVersion, source, sourceUrl, generatedAt, wordCount, variantCount, skippedLineCount, deduplicatedVariantCount, data map).
- `packages/shared-data/data/dict/cmudict-stats.json`: derived stats payload (see contract below).
- `packages/shared-data/src/index.ts`: re-export both payloads (and a lightweight type) so consumers import from `shared-data`.

## Generation Requirements (helper scripts)
- `cmudict-to-json` continues to download/normalize CMUDict but writes into `shared-data`’s data directory (ensure directories exist).
- New `cmudict-stats` helper reads the generated CMUDict JSON from `shared-data`, computes stats, and writes the stats JSON next to it.
- Script outputs should remain deterministic and safe for version control; metadata should include a generation timestamp and source URL.
- Keep processing offline-only (no extra network beyond the initial CMUDict fetch).

## Stats Payload Contract (data-only)
Include numeric arrays and small string lists; no prose or localized copy.
- `meta`: { `generatedAt`, `source`, `sourceUrl`, `wordCount`, `variantCount`, `multiplePronunciationCount` }.
- `overview`: aggregate counts (words, variants, share of words with multiple pronunciations).
- `phonemes`: array of items with ARPAbet token, mapped IPA symbol, `tokenCount` (across variants), `wordCoverage` (number and percentage of words containing the phoneme), and `averageTokensPerWord`.
- `stress`: counts of primary/secondary/unstressed markers plus top stress patterns (e.g., `["1"]`, `["1","0"]`, `["0","1"]`) with counts.
- `syllables`: histogram of syllable counts per word (1..N) with counts and percentages.
- `ambiguousWords`: top 50 words by variant count; include up to 6 ARPAbet variants per word and note if more exist.
- `sequences`: include top 30 onset/coda bigrams and top 20 trigrams in ARPAbet with counts; omit this block if payload size would exceed ~1 MB.
- Keep field names stable and small; reserve room for a future `version` or `schema` field.

## Consumption Requirements
- `apps/web` CMUDict consumer (`app/api/g2p/_core/dictionary.ts`) must import the JSON from `shared-data` rather than `@/data/dict`.
- Any other tooling that reads CMUDict must switch to the shared-data export (e.g., future audio-gen or word-mapping scripts).
- Stats page (Next.js App Router) reads the stats JSON via `shared-data`; no direct file reads or extra fetches.
- Localization: all learner-facing labels live in locale files; the stats payload remains numeric/structural only.

## Stats Page UX Requirements
- Surface the following sections with lean, functional UI:
  - Overview cards: total words, total pronunciations, % with multiple pronunciations, generatedAt/source.
  - Phoneme coverage table: IPA-first, ARPAbet as secondary; sortable by frequency/coverage.
  - Stress patterns: distribution (primary/secondary/unstressed) and top stress shapes.
  - Syllable histogram: bar/column view for counts.
  - Ambiguous words: small list/table of the most multi-pronunciation words with their variant count (variants shown in ARPAbet; optionally toggle to IPA via registry lookup).
  - Optional sequence insights: top consonant clusters if included in payload.
- Interaction: light filtering/sorting only (no heavy interactivity). Keep layout responsive and text-forward; avoid marketing visuals.
- Placement: dedicated learner-facing route at `/[locale]/stats` (App Router), linked from the overview navigation; keep locale-aware routing.

## Testing/Validation Expectations
- Shared-data exports should type-check and be importable from both `apps/web` and scripts.
- Helper scripts should succeed when run from a clean checkout (`bun --cwd packages/helper-scripts cmudict-to-json` then stats).
- Payload sizes should remain reasonable for client bundling; if large, gate the stats payload to server-side usage or lazy load.

## Decisions (follow-ups resolved)
- Ambiguous words: cap at top 50, with up to 6 variants shown per word (mark if more exist).
- Sequence stats: include by default with the caps above; drop the block only if size pressure appears.
- Route placement: use `/[locale]/stats`, linked from overview; keep the page lean and responsive.
